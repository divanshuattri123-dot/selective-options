Conflicts, stale snapshots and uncovered gaps halt collection and record the reason. Per-symbol bar flushing waits for recovery; prior bar state is not restored. See `evidence/trade-recovery-01/verification.json`.

The `backfill-trades` command creates a bounded archive for an explicit native-ID range after a saved WebSocket checkpoint. It checks the REST anchor against that checkpoint, validates every consecutive ID, deduplicates page overlap and enforces page/byte/time budgets. Exact REST decimal timestamps are stored under `kraken_rest`; actual HTTP receipt times control historical visibility. Public evidence is in `evidence/trade-backfill-01`. A validated, committed reconciliation plan can now seed an explicitly requested new capture; automatic forward-gap repair is available when explicitly enabled after subscription acknowledgements.

The new `RecoveryBuffer` and `reconcile_while_receiving` component retain incoming records while a bounded backfill is pending, reject duplicates with conflicting economics/timestamps, and release a complete contiguous plan only after validation. Byte/event/deadline overflow fails the attempt and both asynchronous tasks are cleaned up. Plans preserve raw receipt times and expose a separate verification time; `ready_rows` refuses premature or future-source visibility. This component is fixture-tested and replayed against saved public evidence. Its committed plans now support explicit startup handoff; version 0.3.9 connects this to opt-in capture repair.

Recovery plans can be atomically published with their anchor, raw evidence, selected trade IDs, verification marker and outbox entries. The explicit-marker loader reconstructs and revalidates mixed-source plans after restart; missing/changed evidence and incompatible receipt times fail. The marker records verification knowledge time, not a later commit-completion timestamp. Evidence: `evidence/recovery-journal-01/report.json`.

Capture now accepts `--resume-trades-from DATABASE --recovery-marker MARKER_ID`. It copies the validated anchor/raw/marker into the new destination, closes and reloads that database, and only then activates the collector sequence. Both transport identities are retained for duplicate checks. Initial snapshots must connect to the chosen marker; updates before a snapshot, conflicting overlap, stale snapshots and uncovered gaps fail. REST rows remain REST evidence and never enter WebSocket bars. Prior bar state is not restored, and new bars begin partial. The marker selects one book and its explicit through-ID, not later trades in the same source database; other books start fresh. Saved-public replay verified 139 copied rows, 120 selected trades and 17 duplicate identities. Runtime successor/snapshot behavior and interrupted startup are tested with fixtures; no fresh live continuity run is claimed. See `evidence/recovery-handoff-01/report.json`.

The `recover_trade_gap` coordinator now runs bounded REST pagination while buffering caller-routed live events, validates the complete sequence, commits its journal and reloads it through the still-open writer. `collect_range` accepts canonical REST anchors with exact decimal timestamps, enabling a later gap to follow a prior REST tail. Failures cancel/join the receive and fetch tasks. Reports distinguish a failure before publication, an uncertain interrupted publication and a committed marker whose reload failed. Saved-data replay exercised three original public HTTP pages, 17 saved WebSocket records, 137 raw observations and 120 selected trades. The 139-row journal passed both open-writer and closed-database reload. Transport was mocked; no new live-network claim is made. With automatic recovery enabled, the socket handler invokes this coordinator; the separate runtime activation step controls cursor changes and partial bars. See `evidence/gap-coordinator-01/report.json`.

The collector now retains its last accepted immutable trade per book and raises a structured `TradeGap` without advancing any part of an invalid batch. `begin_gap_repair` suspends only the affected book, marks its active bars incomplete, waits for a FIFO writer/consumer barrier and verifies the exact committed anchor. `activate_gap_repair` reloads the marker, delivers unchanged recovery evidence through the existing consumer/outbox path, waits for delivery, then atomically installs the sequence. Cancellation, consumer failure or changed anchor state prevents activation and leaves the book suspended. Buffered/backfilled trades never enter existing bar accumulators. Saved-data evidence is in `evidence/runtime-recovery-01`; Redis delivery failure is fixture-tested, not verified against a deployed server. Version 0.3.9 also invokes these APIs from the opted-in socket handler.

Automatic recovery is opt-in through `ingestion.kraken_auto_recovery_enabled` (default false). A forward native-ID gap after subscription acknowledgements suspends the affected book and calls the tested begin/fetch/activate path. One recovery reader preserves original receipt times and buffers up to 1,000 frames, 16 MiB of encoded payloads and 20,000 trades. Validated consumed trades are removed from replay; other books and unconsumed same-book rows retain their order and timestamps. During storage/delivery waits, the WebSocket client's bounded frame queue supplies backpressure. Invalid controls, offline markets, overflow, disconnects and deadlines fail closed. Source times slightly ahead within allowed skew are awaited using the actual clock within the existing deadline; timestamps are never rewritten.

After the fix, `live-gap-02` recovered omitted BTC ID 109230677, verified recovery through 109230681 and accepted live successor 109230682. The test stopped after about 7.9 seconds; it is neither a soak nor a paper-trading run. No orders or private APIs were used, and Redis was not configured.

## Known limits and outstanding M2 work

Complete historical options bid/ask/depth and underlying trade history; full-universe streaming greeks; remaining cross-venue funding/OI venues and history, plus complete liquidation ledger/history; remaining on-chain metrics; crypto/financial news and classification; CPI/PCE/NFP release schedules and values plus ECB/BoJ calendars; distinct XAU/USD and gold macro references; recovery outside bounded Kraken history, other stream checkpoints and periodic bar crash recovery; a deployed Redis consumer bus; retention purge and sustained rotation/soak validation. Optional BEA and FOMC schedules remain scoped subsets. Finite offline rotation and opt-in periodic committed checkpoints are verified separately. Redis replay is fixture-tested; no real Redis service has been deployed. A restore requeues all events because delivery acknowledgements are not part of the event archive.

Coinbase reference time belongs to its last trade. Kraken's REST quote uses explicitly labelled receipt time and cannot prove source freshness. Public-market prices remain separate from Deribit testnet. PAXG prices are tokenized-gold references, not XAU/USD; PAXG perpetual availability does not establish an options route or fixed loss. RSS publication time is the publisher's claim, not independently verified first publication. First observation is never backdated. Neither missing feeds nor stale data are replaced with invented values.

The original specification requires every M2 feed flowing before later milestone acceptance. The user has separately authorized independent feature/backtester implementation alongside incomplete M2; those implemented research components do not satisfy acceptance of M3 or later strategy/validation milestones. Public-feed and recovery work can continue without provider purchases or account setup. The former desktop development heartbeat was deleted on the user's pause; resuming a coding task does not automatically recreate a recurring automation.

# Finite canonical CoinDesk RSS metadata proof

One real public production-collector request to `https://www.coindesk.com/arc/outboundfeeds/rss?outputType=xml` returned HTTP 200 and 30,250 decoded entity bytes. The publisher supplied no Location header. No redirect was followed and no retry or article-body request occurred. This uses the evidenced direct no-trailing-slash endpoint established by the separate three-request `news-endpoint-discovery-01` proof. Combined this increment makes four public requests: three discovery requests and this one collector poll. The discovery request to the legacy endpoint reproduced HTTP 308 solely to recover its previously uncaptured native Location; this production probe never requests that legacy endpoint.

The independent defused XML DOM compares all 25 native metadata items with the production records, preserving exact decoded XML title, link, GUID and publication-date text plus normalized values. Publisher publication time is a claim; all metadata availability is controlled by the actual local HTTP-response receipt `1791113907590`. Publication dates are never substituted for availability. The 25 news rows and one bound healthy poll record produce `POLL_OBSERVED_VERIFIED` at the saved cutoff. This proves metadata from one finite poll, without independently verified first publication, sentiment, direction, classifications, all-news completeness or continuous history.

All 52 event receipt/source boundary checks pass. Exact duplicate insertion, SQL/Parquet equality, sealed archive checksum, closed read, pure-versus-bounded store quality and reopened quality match. The closed outbox contains exactly the 26 persisted event IDs with `delivered=false`; this establishes pending local delivery only, not deployed Redis delivery. The bound successful health record is a sink-acceptance claim, not an atomic commit proof.

The collector and verifier remained frozen during the probe. `source-snapshot.py` SHA256 is `97944a8d9a9518685249ac0e3f68a521489b3f5ec2c893f10702fb7ff174565b`; `verification-script.py` SHA256 is `119ad56588ea14908a00b65a85457ec050f14c1df53a148aba5da1a2fbf67a8a`. All nine historical `crypto-news-public-01` file hashes remain unchanged and are recorded before/after in `provenance.json`. The historical HTTP 308 failure, its report, source/verifier snapshots and post-probe wording correction are preserved.

The verifier now records safe native decoded Location header text exactly as evidence and never navigates to it. Only the fixed publisher HTTPS origin or relative location, exact known RSS paths and optional `outputType=xml` query are allowed. Credential-bearing, unknown-path/origin/query, fragmented, control-containing or oversized values store only length and hash. Success and HTTP 308 hook fixtures show exact saved body/header receipt and no second request; these are explicitly mocked tests, not more public attempts.

All 47 verifier tests passed in 7.68 seconds, including 22 additional header/success/refusal/exact-outbox cases. Ruff formatting/lint and strict type checks pass. Finite network limits are one request, 15-second deadline, 2,097,152 decoded bytes and 100 items, with redirects and retries disabled. Test fixtures have zero public calls. The report's documentation-linked field remains false because this finite verifier does not itself fetch the publisher documentation; the companion discovery independently preserves and verifies that primary publisher page.

No private API, credential, account change, purchase, signal, paper run, order or production enablement occurred. M2 remains partial and full elapsed validation is pending. This newly verified source does not by itself enable trading.
